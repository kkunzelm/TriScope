  ---
  Laser Scanner Module — Technical Specification for Integration

  1. Overview and Scope

  This describes only the scanner-specific logic that sits on top of existing camera and XYZ-stage abstractions. The
  receiving application already has:
  - A camera object that returns 8-bit monochrome frames (row-major, uint8_t[])
  - An XYZ controller that can move to absolute positions in mm and reports done asynchronously
  - These are accessed through interfaces similar to ICamera and IMotionControl described below

  The scanner adds:
  - Laser line extraction (subpixel)
  - Triangulation (2D pixel → 3D world coordinate)
  - Calibration (Z-axis scale, Y-axis scale, optical axis centre)
  - Stop-and-go scan loop
  - PLY export

  ---
  2. Required Interface Contracts

  The new code interacts with existing hardware only through these two abstractions. The signatures must be respected
  exactly.

  ICamera (what the scanner calls)

  struct Frame {
      std::vector<uint8_t> data;  // row-major, 8-bit mono
      int width{0};
      int height{0};
      bool valid() const { return !data.empty() && width > 0 && height > 0; }
      uint8_t pixel(int col, int row) const { return data[row * width + col]; }
  };

  enum class AcquisitionMode { Continuous, SoftwareTrigger };

  struct CameraParams {
      double exposureUs{500.0};
      double gainDb{0.0};
      int    roiOffsetY{0};   // 0 = full frame
      int    roiHeight{0};    // 0 = full frame
      AcquisitionMode mode{AcquisitionMode::SoftwareTrigger};
  };

  // Methods the scanner calls:
  bool   configure(const CameraParams&);
  bool   startAcquisition();
  Frame  captureFrame(int timeoutMs = 5000);  // returns invalid Frame on error/timeout
  void   stopAcquisition();
  int    sensorWidth()  const;
  int    sensorHeight() const;

  Important: captureFrame() is synchronous and blocks the calling thread until a frame arrives or timeout expires.
  During a scan it is called from the scan worker thread, never from the GUI thread.

  IMotionControl (what the scanner calls)

  struct Position3D { double x{0.0}; double y{0.0}; double z{0.0}; };

  // Coordinate convention: software / ISO 841
  //   +X = scan direction (table moves object past laser)
  //   +Y = lateral (across laser line width)
  //   +Z = up (Z=0 at home/reference surface)

  // Methods the scanner calls:
  bool       moveAbsolute(Position3D target);   // blocks until motion complete
  bool       moveRelativeX(double deltaXMm);
  Position3D currentPosition() const;
  Position3D travelRange()     const;           // populated after calibrate()

  3. Calibration Parameters

  All scanner math uses one CalibParams struct. These 5 numbers fully describe the optics and are saved/loaded as
  JSON.

  struct CalibParams {
      double theta_rad{0.436332}; // triangulation angle Θ (~25°) — informational only, not used in computation
      double x_ref{640.0};        // camera column where laser line hits Z=0 reference plane
      double scale_z{0.050};      // mm per pixel of horizontal (column) shift (from Z calibration)
      double scale_y{0.017};      // mm per pixel in vertical (row) direction (from Y calibration)
      double cy{512.0};           // camera row of optical axis (world Y = 0)
  };

  JSON representation (loaded at startup with --calib-file):
  { "theta_rad": 0.436332, "x_ref": 640.0, "scale_z": 0.050, "scale_y": 0.017, "cy": 512.0 }

  4. Laser Line Extraction

  Purpose: Given one 8-bit monochrome camera frame, find the subpixel column position of the laser line centre in
  each camera row. The laser line runs vertically in the image (parallel to world Y).

  Input: Frame (8-bit mono) + ExtractorParams
  Output: LaserProfile — one double colPosition per row; -1.0 means no valid laser in that row

  struct ExtractorParams {
      uint8_t    threshold{50};            // minimum pixel value to consider as laser (0–255)
      int        windowCols{5};            // CoG fallback: restrict to ±windowCols around peak (0 = full row)
      PeakMethod method{PeakMethod::Gaussian};
      double     medianRejectCols{50.0};   // post-filter: invalidate rows deviating more than this from the median (0 = disabled)
  };

  struct LaserProfile {
      std::vector<double> colPositions;  // length == frameHeight; index = camera row
      int frameWidth{0};
      int frameHeight{0};
      int validRows{0};
  };

  Algorithm (per row):

  Step 1 — Find peak column:
    scan all columns in this row, find the column with the maximum pixel value (peakVal, peakCol)
    if peakVal ≤ threshold → colPositions[row] = -1.0, skip to next row

  Step 2a — Gaussian 3-point log-interpolation (default, Weber 1995):
    requires peakCol > 0 and peakCol < width-1
    i0 = pixel at (row, peakCol-1)
    i1 = pixel at (row, peakCol  )
    i2 = pixel at (row, peakCol+1)
    if i0 > 0 and i2 > 0:
      li0 = log(i0),  li1 = log(i1),  li2 = log(i2)
      denom = li0 - 2*li1 + li2
      if denom < -1e-10:
        colPositions[row] = peakCol + 0.5*(li0 - li2) / denom
        continue to next row   ← this is the preferred result

  Step 2b — Center-of-Gravity fallback (if Gaussian fails or is disabled):
    colMin = max(0, peakCol - windowCols)  [or 0 if windowCols==0]
    colMax = min(width, peakCol + windowCols + 1)  [or width if windowCols==0]
    sumW = sumWX = 0
    for col in [colMin, colMax):
      v = pixel(row, col)
      if v > threshold:
        sumW  += v
        sumWX += v * col
    if sumW > 0:
      colPositions[row] = sumWX / sumW

  Step 3 — Median outlier rejection (post-filter):
    Collect all valid colPositions, compute median.
    Invalidate any row whose colPosition deviates more than medianRejectCols from the median.

  The Gaussian method gives ~20× subpixel precision on well-formed laser peaks. CoG is the fallback.

  5. Triangulation Model

  Geometry: Double-telecentric laser triangulation. The laser projects a vertical line (parallel to world Y) in the
  scene. The camera views from triangulation angle Θ. A change in surface height Z shifts the laser stripe
  horizontally (column direction) in the raw camera image. The table moves the object along world X.

  Forward projection (pixel → world), in the raw camera frame — no rotation applied:
  z_world = (col_px - x_ref) * scale_z     [mm]
  y_world = (cy     - row_px) * scale_y    [mm]
  x_world = table_x_mm

  Where:
  - col_px = subpixel column from laser line extractor (positive right)
  - row_px = camera row index (positive down)
  - table_x_mm = current X position of the motion controller

  Sign convention:
  - col_px > x_ref  →  z_world > 0  (surface above Z=0 reference plane)
  - row_px < cy     →  y_world > 0  (surface above optical axis in world Y)

  Implementation:
  // For each valid row in the LaserProfile:
  if (colPositions[row] < 0.0) continue;
  double z = (colPositions[row] - calib.x_ref) * calib.scale_z;
  double y = (calib.cy          - row)          * calib.scale_y;
  // 3D point: (table_x_mm, y, z)

  One LaserProfile from an H-pixel-tall frame produces at most H 3D points per scan step.

  6. Calibration Procedures

  6.1 Z-axis calibration (scale_z and x_ref)

  Procedure: Move the stage to N known Z positions (minimum 2, typically 5–10) while a flat reference surface lies
  under the laser. Capture a frame at each position. Compute the mean laser column at each Z.

  Data structure:
  struct ZCalibPoint {
      double zMm;      // Z position from controller (mm, software coords)
      double colMean;  // mean of all valid colPositions in the LaserProfile
  };

  Math (least-squares linear regression):
  Model: col = a + b * z  where a = x_ref, b = -1 / scale_z

  n = number of calibration points (minimum 2)
  sum_z   = Σ zMm
  sum_c   = Σ colMean
  sum_z2  = Σ zMm²
  sum_zc  = Σ zMm * colMean

  denom = n * sum_z2 - sum_z²
  b = (n * sum_zc - sum_z * sum_c) / denom
  a = (sum_c - b * sum_z) / n

  x_ref   = a
  scale_z = -1.0 / b    ← b < 0 for a vertical laser line; scale_z is always positive

  Physical explanation: as stage Z decreases (stage moves down, surface moves away from camera), the laser
  column increases (stripe shifts right), so b = Δcol/Δz < 0. Therefore scale_z = -1/b > 0.
  Validation: reject calibration result if scale_z ≤ 0.

  Wizard motion sequence (as implemented):
  1. Capture frame at current Z = Z_base → point 1
  2. Move to Z_base − Δz → capture → point 2
  3. Move to Z_base − 2Δz → capture → point 3
  ... repeat for N steps ...
  N+1. Return to Z_base
  N+2. Fit with the above formula

  6.2 Y-axis calibration (scale_y and cy)

  Procedure: Place an object of known physical width W (in world Y) across the laser line. The object's edges
  appear as step transitions in the column positions along the vertical laser line. Detect the two edge rows.
  One frame is sufficient.

  Math:
  deltaRows = bottomRow - topRow       (row distance between edges)
  scale_y   = knownWidthMm / deltaRows (mm per pixel)
  cy        = (topRow + bottomRow) / 2 (optical axis row)

  Edge detection (5-row sliding window):
  Scan colPositions[] top-to-bottom with a window of width kWin=5 rows.
  For each pair (colPositions[r], colPositions[r+kWin]):
    gradient g = colPositions[r+kWin] - colPositions[r]
    track the row index of maximum positive g  → one edge
    track the row index of maximum negative g  → other edge
  Require |g| ≥ 5 pixels to count as a valid edge.
  Return lo = min(topIdx, bottomIdx), hi = max(topIdx, bottomIdx).

  7. Stop-and-Go Scan Loop

  This is the core scanning algorithm. It runs in a worker thread (not the GUI thread) to avoid blocking the UI.

  Input:  startX, endX, stepMm, CalibParams, camera, motion controller
  Output: accumulated PointCloud → written to PLY file

  1. Configure camera (exposure, gain, ROI, Continuous mode)
  2. Start camera acquisition
  3. Move to startX (absolute)

  4. Build position list:
     xPositions = [startX, startX+step, startX+2*step, ..., endX]
     (always scan in one direction to eliminate backlash)

  5. For each xMm in xPositions:
     a. moveAbsolute({xMm, startY, startZ})   ← blocks until motion done
     b. frame = captureFrame(5000 ms)          ← blocks until frame arrives
     c. if frame invalid: skip (or throw, depending on error policy)
     d. profile  = extractLaserProfile(frame, {threshold})
     e. stepCloud = projectTo3D(profile, xMm, calib)
     f. cloud.append(stepCloud)
     g. emit progress(stepIndex, totalSteps, xMm)

  6. Stop camera acquisition
  7. Write cloud to PLY
  8. Emit done signal with point count

  Threading in the existing application: The scan loop must not run on the GUI thread. Options:
  - Run it in a QThread-managed worker: emit progress signals via Qt::QueuedConnection
  - Or use QMetaObject::invokeMethod with Qt::QueuedConnection for each step's stage move (signal-driven stop-and-go,
  as in the current GUI implementation)

  The signal-driven approach (used in ScanSetupWindow) avoids blocking any thread: the stage controller emits
  scanStepReady(xMm) when motion completes, the GUI slot then captures the frame and calls the extractor and projector
   synchronously. This keeps the motion thread free.

  8. PLY Export

  Standard PLY, property float x y z, 3 × float32 per vertex.

  Header (ASCII regardless of format):
    ply
    format binary_little_endian 1.0   (or "ascii 1.0" for debug)
    element vertex <N>
    property float x
    property float y
    property float z
    end_header

  Body (binary_little_endian):
    For each point: 12 bytes = [x:float32][y:float32][z:float32], little-endian

  Coordinates are in mm. CloudCompare reads this format directly. No normals, no colours.
